# Proposal

## Why

前端开发完成后，开发者需要在真实浏览器中确认功能正确，并留下以后可重复执行的回归测试；目前这通常需要逐项目配置工具、手写用例和人工排查失败。WebPilot 将这些步骤打包为一个 Codex 插件，以框架无关、默认零侵入的方式接入项目，形成“需求与改动 → 浏览器验收 → 证据报告 → 回归资产”的闭环。

## What Changes

- 提供本地 Codex 插件，包含验收 Skills、本地 MCP 服务和独立 CLI；浏览器执行与回归复用同一套引擎。
- 支持 URL、已运行服务和项目目录三种入口，自动发现项目启动线索，并支持工作目录、命令、地址的显式覆盖。
- 插件管理自身的测试运行时，不要求目标项目安装依赖、使用特定框架、修改组件或添加 test id；项目配置和测试导出由用户选择。
- 从用户需求、OpenSpec、已有回归和可选 Git diff 生成验收计划，记录断言来源、覆盖范围和未验证部分。
- 在独立 Chromium 上下文中执行交互与确定性断言，默认录制每次浏览器尝试的完整流程视频，并采集截图、trace、控制台及相关网络失败；支持已有登录态和项目数据准备配置。
- 将结果区分为通过、失败、阻塞和无法确定，提供可复现步骤及有证据支持的诊断。
- 保存结构化回归用例，在不调用模型的情况下重跑，并导出可独立运行的 Playwright 测试包。
- 通过跨框架样例和已知缺陷集验证接入、发现问题和回归稳定性。

首版默认：本地优先，TypeScript / Node.js 22+，Chromium，显式触发验收，Codex 承担 AI 推理，插件不另行要求模型 API key。React/Vite、Vue/Vite、Next.js、静态 HTML 和 monorepo 是兼容验证样例，而非框架白名单；语义不足的 Canvas 流程可报告能力缺口，视觉自动操作作为后续增强。

首版暂不包含公开插件目录发布、浏览器扩展、生命周期自动触发、多浏览器矩阵、视觉基线管理、完整无障碍审计、任意网站全自动遍历或自动修改产品代码。CLI 可供 CI 调用，团队用例管理和 CI 平台集成留待后续。

## Capabilities

### New Capabilities

- `project-onboarding`: 框架无关的目标接入、配置发现、服务生命周期、登录态与测试数据准备。
- `acceptance-planning`: 基于需求和改动生成可追溯验收计划，管理候选断言、范围与覆盖缺口。
- `browser-verification`: 浏览器会话、语义交互、等待、断言、证据采集及能力边界。
- `test-reporting`: 结果状态、失败诊断、脱敏证据、覆盖说明与运行清单。
- `regression-assets`: 用例保存、确定性重跑、Playwright 导出和测试变更追踪。
- `codex-plugin-integration`: 插件打包、Skills/MCP/CLI 工作流与运行时就绪检查。

### Modified Capabilities

无。当前项目没有已有能力规格。

## Impact

- 本仓库新增插件包、TypeScript 测试引擎、MCP 服务、CLI、验收 Skills、报告模板及兼容性测试样例。
- 主要依赖为 Playwright、MCP SDK 和结构校验库；安装时获取插件依赖，浏览器资源需要首次配置及就绪检查。
- 目标前端项目默认不产生依赖或源代码变更；选择导出或保存项目配置时才写入指定位置。
- 浏览器运行会访问目标应用，业务写入依照项目测试环境与数据配置执行；录像可能呈现登录态和页面敏感内容，默认作为敏感本地证据保留，支持关闭并遵循运行保留期，不将媒体内容提供给 Codex。
- 本地 MCP 与 CLI 的对外接口需要版本化；具体宿主加载与发行格式以实现时官方文档和实机兼容验证为准。
