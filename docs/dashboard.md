# 本地测试中心

WebPilot 的计划执行、回归及浏览器探索会话会自动登记到当前系统用户共享的本地看板。不同聊天、项目和 `dataDir` 使用同一个服务。verify/replay 工作流先调用 `dashboard_open`，在耗时测试开始前打开看板；后续测试直接加入现有页面。

打开前由共享服务统一检测：自动调用、CLI 和 Codex 内打开的页面都计入同一次打开记录；多个聊天同时请求时仅一个请求取得打开资格。本次服务运行期间已经打开过，或正在打开时，后续调用返回 `shouldOpen:false`，不再弹出新页面。此时只展示链接，不应再次调用浏览器打开该链接。`open:false` / `--no-open` 仅获取链接，不占用打开资格；打开失败可重试。

## 查看与管理

```sh
node dist/cli/index.js dashboard open
node dist/cli/index.js dashboard status
node dist/cli/index.js dashboard open --run RUN_ID
node dist/cli/index.js dashboard open --force
node dist/cli/index.js dashboard import --data-dir /path/to/older-webpilot-data
node dist/cli/index.js dashboard stop
```

看板采用浅灰侧栏与白色工作区。侧栏可切换所有运行、正在执行、失败记录和已归档；状态筛选写入页面地址，刷新后保留。总览将统计收成一行，以紧凑列表显示各条测试的阶段、耗时、最近步骤缩略图和独立进度；窄屏将日期与耗时移到运行名称下方。可以搜索项目、目标或测试名称，按状态筛选及翻页。勾选两条运行后点击“并排观看”；详情以时间线和画面分栏展示，可切换实时画面、步骤详情、截图、报告和录像；窄屏与并排观看使用纵向布局。点击步骤查看预期、实际结果及原始诊断。候选检查、重试不稳定、清理问题和覆盖缺口独立显示。

固定计划显示用例完成数量；增量探索会话只显示步骤和时间线，不显示虚构百分比，也不因正常关闭而宣称整体验收通过。直播断线、执行器断线和正式业务失败分别显示。主动关闭页面后需要重新打开，或出现会话过期提示时，可点击返回的新访问链接；需要再次弹出页面时，执行 `dashboard open --force` 或调用 `dashboard_open` 并传入 `force:true`。

服务在测试结束后仍然可访问。关闭网页不停止测试；显式停止服务也不取消其他执行器。已连接执行器只尝试重连，不在用户停止后立刻重启服务；下次新测试或显式打开会重新启动。刷新页面及重启服务会从已登记文件恢复历史，旧报告没有进度日志时展示已有报告，不补造执行过程。

## 配置与自动化

```sh
node dist/cli/index.js run --plan plan.json --no-open
node dist/cli/index.js run --plan plan.json --no-dashboard
node dist/cli/index.js dashboard open --no-open
```

`--no-open` 保留服务和进度登记，避免自动打开浏览器；`--no-dashboard` 关闭本次执行的服务连接。`WEBPILOT_DASHBOARD=0` 对进程及其子进程禁用自动看板接入，本地报告及进度仍可保存。CLI 正常测试的 stdout 保持原 JSON，链接和降级说明写 stderr；业务退出码保持原规则。

`WEBPILOT_DASHBOARD_DIR` 或 CLI `--dashboard-dir` 只覆盖共享服务的状态目录，用于显式隔离环境；它独立于 `WEBPILOT_DATA_DIR` / `--data-dir`。默认目录为 macOS `~/Library/Application Support/webpilot/dashboard`、Linux `$XDG_STATE_HOME/webpilot/dashboard`（默认 `~/.local/state`）和 Windows `%LOCALAPPDATA%/webpilot/dashboard`。测试使用临时状态目录并显式停止服务，避免污染用户的看板。

默认首选回环端口 4318，优先复用已有端点记录；占用时选择系统分配端口，以工具/CLI 返回值为准。`endpoint.json`、内部凭证、索引和日志仅存于本机状态目录；POSIX 目录和文件分别使用 0700 / 0600。服务检查协议和实例身份，无法验证已有实例或协议不兼容时诊断并降级，不杀死已有进程。没有图形环境时输出链接继续测试。不安装开机服务。

## 直播与证据

`target.evidence.live` 默认 true，独立于 `video`。只有观看当前运行时才启动额外直播；最后观看者退出后停止 CDP 采集。总览的缩略图复用步骤截图。无头 Chromium 可直播，切换页面、用例和尝试时跟随执行器选中的页面。

```json
{"url":"http://localhost:3000","evidence":{"live":false,"video":true}}
```

总览缩略图、截图页与步骤详情中的截图均可点击放大，也可聚焦后按 Enter 打开。预览默认适应窗口，可切换原始尺寸并滚动查看细节，或在新标签页打开原图；按 Esc、点击遮罩或关闭按钮返回，保留当前页面位置。

截图仍经过现有 masks 与秘密值处理。直播直接输出浏览器画面，**可能包含未经脱敏的敏感内容**，与本地录像使用相同访问边界；关闭直播不会关闭进度、截图或已启用录像。直播帧只驻留内存，不保存为额外文件，不进入 MCP/模型媒体输出或独立导出包。

初始传输参数为 JPEG quality 65、最大 1280×720、发送上限约 8 FPS。静止页面不一定产生新帧，所以界面分别展示连接状态与最近画面时间。来源及观看连接有大小和缓冲上限，拥塞丢弃旧帧或断开慢观看者；及时确认 CDP 帧，网络发送不阻塞测试。参数是上限，实际延迟和开销以验收记录为准。

当前连接单帧和 WebSocket 缓冲上限均为 2 MiB；存在未发送数据时不再加入新画面，避免媒体持续挤占控制消息。2026-10-15 在 macOS arm64 的三组交替对比中，两条独立 MCP 测试不观看平均 3488 ms，双路观看平均 3424 ms，差异在本次短样例的噪声范围。观看时各组帧传输 p95 为 3–4 ms，Dashboard 与测量脚本所在 Node 进程平均 CPU 时间约 110 ms、平均峰值 RSS 增量约 7.72 MiB；CPU/内存不包含执行器和 Chromium，传输延迟不包含 CDP 采集及图片绘制。该页面大部分时间静止，这些数据不代表动画密集页面或端到端视觉延迟承诺。

开发者可在源码仓库运行 `npm run benchmark:dashboard` 复测；原始数据写入 `.webpilot/reports/dashboard-acceptance/benchmark.json`。完整验证范围及桌面宿主待验项见[验收记录](dashboard-acceptance.md)。

录像继续使用原有 WebM 流程，上下文关闭后定稿；详情支持播放、暂停和拖动。未启用、未定稿、生成失败或过期时有明确提示。录像保留期沿用每次运行 `retentionDays`，默认 7 天；新增进度日志与运行一同清理，活跃运行不被过期清理。服务索引失效后不再提供已删除产物。

## 进度协议与恢复

运行目录新增 `live.json` 和 `events.jsonl`。事件协议 v1 包含 `runId`、每运行递增 `seq`、时间、事件类型及适用的 case/attempt/step/page 标识。事件先脱敏、串行追加本地文件，再通知共享服务；同一运行只有一个日志写入者。服务不接收运行绑定对象或认证头。

```sh
node --input-type=module -e 'import {readFile} from "node:fs/promises"; import {parseEvents} from "./dist/dashboard/projection.js"; const result=parseEvents(await readFile(process.argv[1],"utf8")); console.log({events:result.events.length,partial:result.partial,invalid:result.invalid});' /path/to/run/events.jsonl
```

恢复只读取完整行，对重复事件去重，遇到缺口展示限制；未完成尾行不影响之前的完整记录。最终有效 `report.json` 优先于中途投影，探索结果来自 `session.json`。每事件不强制 fsync，不保证断电零丢失。进度写入及上报失败有界降级，仍尝试保存原报告。

执行器约每 3 秒发送心跳，约 15 秒失联后显示连接丢失。只有确认执行器退出且没有最终报告时，才标记运行中断；连接丢失不能推导正式业务失败。迟到的有效报告可以完成状态收敛。

## HTTP 与本地访问

服务只监听 `127.0.0.1`，校验 Host、来源和访问凭证。打开链接通过 fragment 中的短期一次性凭证换取 HttpOnly、SameSite=Strict 的网页会话，随后立即移除 fragment。内部凭证不进入网页链接。不要公开内部状态目录或把敏感本地打开链接分享给其他人。

| 接口 | 含义 |
|---|---|
| `GET /api/runs` | 分页列表；`status/project/page` 参数及总览计数 |
| `GET /api/runs/:id` | 完整可读投影和每运行游标 |
| `GET /api/events` | 总览 SSE，连接时 reset，变化时 changed |
| `GET /api/runs/:id/events` | 详情 SSE，以 state 发送完整投影及 seq；重连重新同步 |
| `WS /api/runs/:id/live` | 状态文本和有身份、epoch、序号的二进制画面 |
| `GET /api/runs/:id/report` | 已保存正式报告或探索记录 |
| `GET /api/runs/:id/artifacts/:artifactId` | 已登记截图/快照/控制台/网络证据及录像；支持 Range |

详情 SSE 使用完整投影替代逐事件前端重放：连接时先发当前状态，再串行接收变化，游标反映已应用日志位置。总览重启后使用新的实例游标触发 reset。慢订阅被有界断开，重新连接恢复当前完整状态。内部 `/internal/*` 只允许持独立凭证的执行器，浏览器 Origin 不能访问。

浏览器控制台在已登录的看板中可运行以下只读样例；它不会输出内部凭证：

```js
const listing = await fetch('/api/runs').then(r => r.json());
const id = listing.runs[0]?.id;
if (id) {
  const stream = new EventSource(`/api/runs/${id}/events`);
  stream.addEventListener('state', event => console.log(JSON.parse(event.data).seq));
  // 完成查看后 stream.close()。
}
```

文件接口只通过运行内的证据 ID 映射访问，不接受任意本地路径。原始 trace、登录态、绑定值和内部凭证不进入通用文件接口；路径逃逸或符号链接逃逸被拒绝。页面证据作为文本渲染，报告原文不能执行脚本。

## 构建、验证与回滚

`npm run build` 先编译 TypeScript，再把前端构建到 `dist/dashboard/public`。Vite 只清理该静态子目录，不能删除 CLI/MCP 编译产物。`npm test` 自动禁用用户级自动看板；专用集成测试显式使用临时服务。发行包包含编译后服务、静态页面及运行依赖，目标项目不增加依赖。

回滚前先运行 `dashboard stop`，再恢复上一插件版本。旧 JSON/Markdown 和播放器仍可直接打开，新进度文件无需迁移。独立 Playwright 导出仅携带执行所需的进度/所有权辅助模块，关闭看板接入和直播，不依赖 ws、React 或已存在的媒体文件。

## 运行标题与重命名

新探索任务使用创建时传入的验证目标作为标题，例如“验证 MP4 下载流程”。未提供 title 时按项目名、网站 host 依次生成默认名称；信息未知时保留“浏览器探索会话”。正式套件继续使用测试范围名称。已有通用名称且目标已知的记录会获得对应的显示默认名称，原始执行文件不会因此改写。

在运行列表行或详情的 `⋯` 菜单选择“重命名”，修改后点击“保存名称”。输入默认选中当前名称，取消、关闭或 Escape 不保存。名称限去除首尾空白后的 1–120 字符；保存失败保留输入供重试。当前、归档和执行中的记录均可改名，执行期间归档和删除仍受原有结束状态保护。

手动名称优先于创建名称与默认名称，刷新、服务重启及重新导入后保持；列表搜索、详情和随后打开的删除确认使用相同显示名称，其他页面同步更新。名称单独保存在运行内的 `title.json`，不改写报告、会话、事件、runId、结果或证据，也不改变归档及永久保存属性。名称文件损坏时显示原名称并提示，可重新保存名称修复；永久删除运行时一并删除显示名称。名称允许重复，日期与状态仍独立显示。

## 归档与永久删除

在运行行右侧 `⋯` 或运行详情菜单选择“归档并永久保存”。记录从默认列表与统计移出；在“记录范围”切换到“已归档”即可查看，原详情链接、截图、报告及录像继续可用。归档提示的“撤销”或菜单的“恢复到当前记录”会将其移回当前列表。归档后永久保存，恢复后仍显示“永久保存”，不再受到自动保留期或 `prune --days` 清理影响；已有证据缺口不会因此恢复。

选择“删除…”会先弹窗展示标题，说明本次报告、截图、录像和执行记录将永久删除、无法恢复，已保存的回归用例保留。点击“取消”、关闭或 Escape 均不删除；只有点击“永久删除”才提交。已保存用例、其他运行、项目文件与独立导出包不会随运行删除。执行中、采集证据中、清理中或仅失联但未确认终止的运行不可归档或删除，菜单显示原因。

旧版探索会话没有 `live.json` 和事件日志时显示“历史记录”，不计入正在执行；未保存的时间、时长显示“时间未知”“时长未知”。有效会话若明确关闭，或包含旧版关闭流程写入、位于本运行录像目录且可读取的非空定稿录像，可以归档和确认删除。仍标记未关闭、没有定稿依据、执行元数据损坏或已有事件日志但结束未确认的记录继续禁止管理；不会把缺少执行器身份当作系统 PID 1，也不会伪造测试结果。

“批量管理”使用独立选择，不受“并排”两条限制。“全选当前页”只选当前页可管理运行；切换范围、筛选、搜索、分页或退出管理会清空选择。批量删除弹窗展示数量和固定标题列表，后台新增运行不会自动加入。成功与失败逐项反馈，成功项移除，仍可见的失败项保留供重试；删空末页会回到有效页。其他已打开页面同步列表、统计与详情，已删除的详情显示“该运行已被删除”。

删除无回收站。若文件清理失败，界面说明“删除待完成”并提供“重试清理”；服务重启会继续处理，完成前不宣称磁盘空间已释放。内部清理区不可从网页访问，也没有恢复入口。运行及永久保存状态会在服务重启、索引重建和重新导入存储根后恢复，已经删除的运行不会重新出现。

归档文件由当前版本清理规则保护。升级时应同时更新共享 Dashboard 与 CLI/MCP 执行器；回滚不能直接运行忽略永久保存标记的旧清理器，应使用包含该保留规则的构建或暂停旧版 prune。

## 测试前覆盖计划

侧栏“覆盖计划”进入 `/plans`，可查看未启动浏览器的清单、待审阅及仅生成记录；`/plans/<coverageId>` 是稳定详情入口。完整清单按来源、优先级、本次安排筛选，展开查看前置条件、操作、预期依据和补充理由。审阅和采用在聊天中完成，页面不提供审批或编辑器。

运行详情新增“覆盖清单”标签，使用运行自身保存的快照，展示已选/未选、未执行原因、初始及新增场景、需求关联和版本历史，并与步骤证据对账。规划记录不计入活动运行数量，不因没有执行器心跳被标为失联。原计划过期时已归档运行的快照仍可查看；旧运行明确说明没有执行前清单。

计划列表/详情与其他接口采用相同本机认证和来源校验，只读取已登记 ID。Dashboard 暂不可用时清单保存在本地，测试可继续；清单本身无法持久化时，执行器不启动依赖它的新业务操作。

当前服务通过状态接口的 `capabilities.coveragePlanning:1` 声明规划能力。遇到仍在运行的旧版服务，执行器不强制替换服务；计划工具不返回无效详情链接，增量规划会话保留本地记录并提示更新、重启测试中心。`WEBPILOT_DASHBOARD=0` 同时禁用自动接入和规划链接登记。

专项验收步骤、测试覆盖和截图见 [测试前覆盖规划验收](pretest-coverage-acceptance.md)。
